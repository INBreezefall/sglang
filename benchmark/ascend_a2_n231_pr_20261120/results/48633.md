# Public NPU paged allocator and cold JIT specialization

Upstream main `ea442ff4ab19171212a9ecaa0e175d0f2dd2a595` and rebased PR `7cf8b1dbf44d831d62f7b08223937d30c2149945` ran on the same physical Ascend 910B4-1. Each fresh process saw one NPU and started with an empty Triton cache. Source verification covered 8,394 main files and 8,395 candidate files from the runtime and registered-test tree. Both arms exercised the public alloc_extend_indices operator and its actual installed Triton adapter.

| Fresh process order | Compiled allocator NPU binaries | First calls across 11 lengths (s) | Warm call median (ms) |
| --- | ---: | ---: | ---: |
| 1, main | 8 | 37.576 | 0.3535 |
| 2, PR | 3 | 23.590 | 0.3580 |
| 3, PR | 3 | 23.810 | 0.3539 |
| 4, main | 8 | 38.043 | 0.3533 |

Eleven positive extend lengths [1, 17, 65, 128, 257, 513, 1025, 2047, 2048, 2049, 4097] used 128-token pages. Every first-call slot was checked against an independent contiguous-index reference. The four subsequent mixed/boundary cases checked the complete slot sequence and the remaining free-page list, including an empty extend, partially filled prefix pages, multi-block extends and the 201-page fallback. All four processes produced the same reference hashes. Extra boundary checks ran after the timed binary snapshot.

Mean first-call totals changed from 37.810 to 23.700 seconds (-37.32%). The mean of the two warm medians per arm changed from 0.3534 to 0.3559 ms. Cold timings include compilation, allocator work and device synchronization. The measurement covers the allocator and its specialization cache.

The registered test and three adjacent allocator suites reported `22 passed, 15 warnings, 9 subtests passed in 9.87s`. The same launch-contract test on unmodified main exposed the four shorter bounds. The public operator and Triton adapter in the measured ARM64 wheel matched the linked upstream Git blobs.
