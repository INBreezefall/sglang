# Ascend transport validation for the four-host comparison

On the initial stock MemFabric 1.1.4 configuration, both decode hosts loaded all eight local model shards and then failed to allocate the default 128 MiB RDMA staging region. Both endpoints started with the documented process-local `HYBM_RDMA_SWAP_SPACE_SIZE=0` option and pre-registered addresses. A 1 MiB device transfer and a separate 234-view model-shaped transfer succeeded. The full service subsequently reported `RaSendWr` error 528102 while replaying requests. These failed service attempts establish an environment limit for this setup. [MemFabric v1.1.4 staging implementation](https://gitcode.com/Ascend/memfabric_hybrid/blob/c01f3ad842b9ff7412681a44b67141ce7a124c6d/src/hybm/csrc/data_operation/host/hybm_data_op_device_rdma.cpp).

The four hosts reported Ascend driver 25.2.3 and firmware 7.7.0.10.220. The Ascend Direct 0.3.14 Mooncake engine also passed the 1 MiB two-pair device check. Its full service using a common CANN allocation-span fixture hit `aclrtMemGetAddressRange` status 207000 on all four hosts. The fixture helper is byte-identical to the allocation query in [PR #48537 at its tested head](https://github.com/INBreezefall/sglang/blob/877b20c1303ae59de3af2c9d82f1bfd11c4b8f57/python/sglang/srt/disaggregation/mooncake/npu_registration.py), SHA-256 `72ada7ee1d83c54f7913817001ff2697fca7099db9836fe5cc47e8003b82c645`. This follow-up executed the copied helper inside an otherwise matched launcher. The earlier per-PR receipts document successful deployments on the original configuration.

A model-shaped test used 78 K, 78 V and 78 indexer slices, covering 84,344,832 bytes in one transfer. It used NPU 1 on each sender and NPU 2 on each receiver. Mooncake rejected individually registered tensor views. Registering the three underlying allocations accepted the same original 234 addresses and verified all K/V/indexer slices at the destination. A second two-pair test resolved the allocations using `torch.npu.memory_snapshot()` and verified all 234 slices on each host pair. The registration adjustment is shared benchmark setup for the measured PRs.
