# Packed INT8 main KV

### Ascend 910B4 hardware validation · 2026-11-19

Compared `f7e7ccbd9f1b` with `89ddc8785e27`. The production NPU pool builder used the 78-layer GLM-5.2 configuration, 1,024 usable slots and 128-token pages. Each arm ran in two processes. Every process backed up two nonconsecutive host destinations, zeroed the device pages, restored all layers via the native kernel_ascend path, and compared every element including untouched pages. All nine round trips per process passed.

Transfer times are medians across seven warm round trips per process. The measurements include the complete per-layer H2D loop. Physical bytes come from the allocated tensors and registered descriptors. A separate two-request decode compared the real device pool writes and sparse-attention outputs with a float32 reference. BF16 and INT8 used 1152 and 656 bytes per main KV row. Relative L2 error was 0.00243 and 0.00698. Median synchronized attention latency was 0.281 and 0.313 ms respectively. This numerical fixture covers one layer and 16 query heads.
