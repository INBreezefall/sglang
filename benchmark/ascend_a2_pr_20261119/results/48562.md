# Graph-safe INT8 DSA indexer

### Ascend 910B4 hardware validation · 2026-11-19

Compared `89ddc8785e27` with `b476e575d222`. The control was the rebased #48560 head. Both arms ran two-request NPU graphs with 16 logical query heads, 128-dimensional indexer keys and top-k 2,048. Four different live KV-length pairs were replayed in each process. The public test compares the actual BF16 vendor boundary with the PR metadata and INT8 operator path.

| KV lengths | BF16 graph (ms) | INT8 refresh + graph (ms) | INT8 / BF16 |
| --- | --- | --- | --- |
| 65/127 | 0.065 | 0.419 | 6.46× |
| 2304/2464 | 0.065 | 0.421 | 6.49× |
| 2513/2113 | 0.063 | 0.409 | 6.46× |
| 333/987 | 0.063 | 0.433 | 6.84× |

All tested INT8 top-k sets agreed with eager execution and the BF16 reference on the seeded, exactly representable inputs. The INT8 path rebuilt metadata once per forward outside capture, retained its captured storage, and used live KV lengths on replay. The one-indexer-layer timing includes this cost. A separate same-device run captured 21 indexer calls with distinct keys and queries per layer and one shared metadata refresh. Its median across the four length pairs was 0.460 ms for BF16 and 1.060 ms for INT8.

The changed-path CPU suite passed 621 tests and 516 subtests. The staged SGLang Python sources matched the Git blobs for both revisions. [Protocol, reproducible scripts and raw samples](../README.md).
