# #48631 · Packed NZ checkpoint round trip

Upstream main `1ed3e1d04b25ab007b4c80481b7b6e3a36836eb7` and the isolated candidate `50cf45054aae04217bc20d9fead1f3dd4d8f1770` ran on the same hardware. Both revisions ran twice in main, candidate, candidate, main order.

The test read 256 × 512 INT8 bytes from a GLM-5.2 expert down projection, created native FRACTAL_NZ storage, then viewed it as 256 × 128 INT32 packed words. It executed the loader hash, export to safetensors, fresh reload and in-place restore into an existing NZ destination. Each success checked the original reference words, layout and destination data pointer. This is a shard slice.

## Eight-rank checkpoint files

Eight HCCL ranks read the full gate, up and down projection matrices for eight different experts from GLM-5.2 layer 10. The total original payload per distributed run was 150,994,944 bytes. Each rank used two registered parameters and an additional tensor attribute. SGLang wrote its manifest, safetensor files and READY marker, then the probe used its real file reader, in-place application, and rank checksum verification. Complete rank round trips across two groups were 0/16 on main and 16/16 on the PR. A standalone process group supplied the world rank and barrier callbacks.
